---

## 🏛️ Application Architecture

The application is structured into domain-driven features with clear separation between state, presentation, and data fetching:

```
src/
├── app/                  # Application providers and routing shell
├── components/ui/        # Reusable design system primitives (Button, Input, Badge, Card, Dialog, Skeleton, OrderProgress)
├── config/               # Centralized branding, photography, and metadata (site.ts)
├── features/             # Domain logic and state management
│   ├── admin/            # Admin analytics, order inspection, inventory hooks (useAdmin.ts)
│   ├── auth/             # Session state, JWT decoding, role tracking (useAuthStore.ts)
│   ├── cart/             # Server-synchronized Redis cart hook (useCart.ts)
│   ├── catalog/          # Inventory query and stock validation (useInventory.ts)
│   └── orders/           # Real-time lifecycle tracking & polling hooks (useOrders.ts)
├── layouts/              # Dual layouts: StorefrontLayout (public) & AdminLayout (RBAC restricted)
├── lib/
│   ├── api/              # Typed HTTP client with token refresh mutex & service endpoints
│   └── utils.ts          # Class merging (cn) and currency/date formatters
├── pages/
│   ├── admin/            # AdminOverviewPage, AdminOrdersPage, AdminInventoryPage, AdminAnalyticsPage
│   ├── auth/             # LoginPage, RegisterPage
│   └── storefront/       # HomePage, ProductsPage, ProductDetailPage, CartPage, CheckoutPage, OrdersPage, OrderDetailPage
└── types/                # Strict TypeScript contracts mirroring Go protobufs & DTOs
```

## 🌟 Key Capabilities & Architectural Features

1. **Dual Experiences with Strict RBAC**:
   - **Customer Storefront**: Editorial browsing, real-time catalog search, in-stock filtering, live Redis cart mutations, and asynchronous order lifecycle tracking (`Pending ➔ Paid ➔ Ready`).
   - **Admin Operations Dashboard**: Dedicated enterprise layout with operational overview, SKU stock charts, system order audit, inventory adjustments, and microservice mesh status. Gated by JWT role verification (`role: "admin"`).

2. **Resilient Token Authentication & Anti-Storm Mutex**:
   - Stores short-lived access tokens and refresh tokens.
   - Automatically detects `401 Unauthorized` responses and refreshes the token in the background (`POST /api/users/refresh`).
   - Built-in anti-storm mutex prevents concurrent failed queries from initiating multiple refresh calls.

3. **Asynchronous Payment Handoff**:
   - Order creation (`POST /api/customers/:customerID/orders`) returns an initial `pending` order while the backend emits `order.created` to Kafka (`orders.created` topic).
   - The frontend automatically polls the order endpoint until the `PaymentLink` is generated by the payments service, then offers a secure handoff button.
   - Detects development/in-memory payment mode and clearly explains mock transactions to developers.

4. **Synchronous Server-Owned Cart**:
   - Cart operations (`GET`, `POST`, `DELETE`) synchronize directly with the Redis cart service.
   - Zero duplicated or stale authoritative cart copies in browser `localStorage`.

5. **Design System & Visual Quality**:
   - Warm off-white background (`#FAFAF8`), near-black typography (`#141614`), and deep forest green accents (`#0F4A36`).
   - High-quality editorial product photography with resilient fallbacks.
   - Full light and dark theme support via Tailwind CSS variables.
   - Recharts visual analytics and Sonner toast notifications.

## 🚀 Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) v18+ (tested on v24)
- [npm](https://www.npmjs.com/) v9+ (tested on v11)

### Installation

```bash
cd frontend
npm install
```

### Environment Configuration

Create a `.env` file in `frontend/` (or copy from `.env.example`):

```env
# Optional: Set Gateway Base URL (leave empty in local development to use the Vite proxy)
VITE_API_BASE_URL=
```

### Development Server

Start the local Vite development server:

```bash
npm run dev
```

The application will be running at: **`http://localhost:5173`**

### Production Build

Typecheck and generate the production bundle:

```bash
npm run build
```

The output bundle is generated in `dist/`.

## 👑 Evaluating Admin Mode

To evaluate the Admin Operations Dashboard:
1. Navigate to `/register` or `/login`.
2. Register or sign in using:
   - **Email**: `admin@stratum.com` (or `admin@oms.com`)
   - **Password**: `<any secure password>`
3. The Go backend gateway grants this email the `admin` role.
4. The frontend decodes the JWT role claim and reveals the **Admin Console** tab in the navigation bar.
